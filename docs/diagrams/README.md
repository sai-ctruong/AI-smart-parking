# Release diagram checklist

These diagrams are future deliverables. This directory intentionally contains no architecture drawing yet. Generate diagrams only after the corresponding components and connections exist in source code.

1. Read `AGENTS.md`, the current README, the approved SRS if available, and the actual frontend, backend, AI, infrastructure, and test code. Record a source path for every depicted component, relationship, or process step. Treat preliminary handoff notes as context, not implementation evidence.
2. Use the project-local official Archify skill at `.agents/skills/archify/SKILL.md`. Node.js 18+ is required. From the repository root, check the installation with `node .agents/skills/archify/bin/archify.mjs doctor`. The skill package needs no extra install step. Read its `references/repository-authoring.md`, authoring defaults, applicable schema, and example before creating a candidate.
3. Produce source-backed standalone HTML with Archify's `finalize` workflow. For example, after authoring a complete architecture candidate, run `node .agents/skills/archify/bin/archify.mjs finalize architecture <candidate.json> docs/diagrams/architecture.html --repo-root . --quality showcase --json`. Follow the skill's validation and repair instructions; do not copy example nodes as project facts.
4. Export SVG from the validated HTML viewer's Export menu. Verify that each SVG renders directly in GitHub and each standalone HTML opens locally. Keep candidate files and receipts in the skill's recommended `.archify/` working folder, outside the final diagram links.
5. Target `architecture.html`/`architecture.svg` for the system architecture (React frontend, FastAPI backend, PostgreSQL, AI inference, image storage); `ai-ml-pipeline.html`/`ai-ml-pipeline.svg` for PKLot validation, preprocessing, train/validation/test separation, model training, evaluation, and inference; and `end-to-end-workflow.html`/`end-to-end-workflow.svg` for upload, polygon ROI, predictions, occupancy statistics, history, and review. **Only include parts and connections verified in code at release readiness.** If a planned part remains absent, omit it and explain the scope in the documentation.
6. After generation and verification, embed `![System architecture](docs/diagrams/architecture.svg)` in the root README. Link the remaining SVG and HTML files with relative paths. Briefly describe each verified major component, check all links on GitHub, and keep source evidence and validation receipts for review.

The repository now has authenticated parking configuration, snapshot upload, inference integration, history/review APIs, a React operations dashboard, and training code. A real evaluated PKLot checkpoint and approved release baseline are still pending. Do not represent a trained model's performance or a deployment topology that has not been verified.
